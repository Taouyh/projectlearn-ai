# ProjectLearn AI 开发路线图

## 路线图说明

本路线图描述计划，不代表功能已经实现。每个阶段完成后应保留可运行版本，并更新文档中的实现状态。

## Phase 0：项目准备

### 目标

建立公开仓库、开发约定和可启动的前后端骨架。

### 开发任务

- [ ] 创建 GitHub 仓库和基础 README。
- [ ] 创建 `frontend/` 与 `backend/` 工程骨架。
- [ ] 初始化 Vue 3、TypeScript、Vite、Element Plus。
- [ ] 初始化 Spring Boot 3、Java 17、MyBatis-Plus。
- [ ] 配置 MySQL、Redis 和 Docker Compose。
- [ ] 建立统一响应、异常处理和配置文件模板。
- [ ] 创建 `.env.example`，不提交真实密钥。
- [ ] 将 PRD、架构、路线图和开发规范纳入 `docs/`。

### 验收标准

- [ ] 前端和后端可以分别启动。
- [ ] MySQL、Redis 可以通过 Docker Compose 启动。
- [ ] 新开发者能按 README 完成基础环境启动。
- [ ] 仓库没有真实 API Key、密码或用户资料。

## Phase 1 - MVP：学习闭环

### 目标

实现从创建项目到 AI 评估和进度更新的最小可用闭环。

### 开发任务

- [ ] 实现用户注册、登录和项目隔离。
- [ ] 实现学习项目创建、编辑、列表和详情。
- [ ] 支持 Markdown、TXT、PDF 和代码目录/ZIP 的资料导入（按可交付优先级逐项完成）。
- [ ] 保存原始资料、解析状态和可追溯的资料片段。
- [ ] 实现统一 `LlmProvider`、OpenAI-compatible Provider 和 Mock Provider。
- [ ] 生成并编辑知识节点、关系和知识地图。
- [ ] 生成学习路径和知识点讲解。
- [ ] 实现 Mermaid 展示和 AI 导师基础问答。
- [ ] 生成概念、流程、代码阅读等学习任务。
- [ ] 支持文本、代码或 Mermaid 输出提交。
- [ ] 实现基于 Rubric 的 AI 分项评估和掌握状态更新。
- [ ] 实现项目和知识点进度看板。

### 验收标准

- [ ] 用户可以创建一个学习项目并导入资料。
- [ ] 系统可以生成可编辑的知识地图和学习路径。
- [ ] 用户可以学习一个知识点、查看流程图并向 AI 提问。
- [ ] 用户可以完成任务并提交输出。
- [ ] AI 返回带分项分数、证据、薄弱点和建议的评估。
- [ ] 评估结果会更新 `LearningProgress`。
- [ ] 至少一条端到端流程可以在本地部署环境中重复运行。

## Phase 2 - HMDP Demo

### 目标

围绕黑马点评 HMDP 制作可展示、可复现的示例学习项目。

### 开发任务

- [ ] 整理 HMDP 示例资料及其使用说明。
- [ ] 覆盖项目基础、Redis、MySQL、认证、商户查询、缓存、优惠券秒杀等核心知识主题。
- [ ] 校验知识节点的来源文件和前置关系。
- [ ] 为关键知识点补充 Mermaid 业务/技术流程图。
- [ ] 为关键知识点补充任务和评分标准。
- [ ] 跑通至少一个“学习—输出—评估—补弱”的演示路径。
- [ ] 记录 HMDP Demo 的已知限制和复现步骤。

### 验收标准

- [ ] 新用户按文档可以导入或加载 HMDP 示例。
- [ ] 示例知识地图可读、可编辑且来源可追溯。
- [ ] 至少一个核心模块具备完整学习任务和评估结果。
- [ ] Demo 不依赖未公开的本地文件或个人账号。
- [ ] 关键截图或演示步骤可以在 GitHub 文档中复现。

## Phase 3 - Open Source

### 目标

让项目具备可公开协作、可自托管和可持续维护的基础。

### 开发任务

- [ ] 完善英文和中文 README、安装和部署文档。
- [ ] 发布 `LICENSE`、`CONTRIBUTING.md`、`CODE_OF_CONDUCT.md` 和 `SECURITY.md`。
- [ ] 增加 Issue、Pull Request 模板和版本变更记录。
- [ ] 增加基础单元测试、集成测试和端到端验收说明。
- [ ] 提供 Docker Compose 自托管流程。
- [ ] 提供 AI Provider 配置说明和 Mock 模式。
- [ ] 清理示例数据中的敏感信息并说明第三方项目许可。
- [ ] 发布第一个可复现的版本标签。

### 验收标准

- [ ] 新开发者可以仅依据仓库文档完成部署和 Demo。
- [ ] CI 至少能执行构建和基础测试。
- [ ] 贡献者可以依据规范提交一个小型改动。
- [ ] 项目明确标注当前已实现能力和未来计划。
- [ ] 发布说明包含已知问题、配置要求和升级方式。
